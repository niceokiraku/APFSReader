# APFSReader

[English](README.md) | **日本語**

Mac のボリューム(**HFS+ / HFSX** と **APFS**(暗号化なし))を、Windows から**読み取り専用**で開きます。
ディスクイメージと、接続した物理ディスクの両方に対応します。小さなデスクトップアプリが、ボリュームを
エクスプローラー上の普通のドライブとしてマウントします。最小化するとシステムトレイに収まります。

| クレート / プログラム | 役割 | ライセンス |
|---|---|---|
| `core` | パーサーとドライバー(ジャーナル再生つき HFS+、APFS、UDIF `.dmg`、GPT、Apple パーティションマップ、decmpfs)、物理ディスクへのアクセス、ヘルパーとの通信プロトコル | MIT |
| `cli` → `apfsreader` | `parts`、`info`、`ls`、`cat`、`extract`、`disks` | MIT |
| `broker` → `apfsreader-broker` | 管理者権限で動く唯一の部分。物理ディスク 1 台の生データの読み取りを提供します | MIT |
| `mount` → `apfsreader-mount` | WinFsp 経由でボリュームを Windows のドライブとしてマウントします(コマンドライン版と、アプリが使うライブラリ) | GPL-3.0(winfsp-rs) |
| `gui` → `apfsreader-gui` | デスクトップアプリ | GPL-3.0(上記を組み込み) |
| `icon`、`build-resources` | コードで描いたアプリのアイコンと、それを各 `.exe` に埋め込むビルド処理(エクスプローラー、タスクバー、トレイ、ウィンドウで同じ絵になります) | MIT |

## クレジット

APFSReader は、ボリュームをドライブとして見せるために WinFsp を利用しています。

> **WinFsp - Windows File System Proxy, Copyright (C) Bill Zissimopoulos**
> https://github.com/winfsp/winfsp

## ダウンロード

[Releases](https://github.com/niceokiraku/APFSReader/releases) から、インストーラー(`APFSReader-Setup-*.exe`、おすすめ)
またはポータブル版の ZIP を入手できます。実行には WinFsp(無償)が必要です。未導入の場合は、アプリが案内します。
配布物には署名がないため、初回に Windows SmartScreen が警告することがあります(「詳細情報」→「実行」)。

## アプリ

`apfsreader-gui.exe` を実行します(WinFsp のインストールが必要です)。ウィンドウには次が並びます。

- **ディスクイメージ**:「イメージを追加」で追加するか、`.dmg` や生イメージをウィンドウにドロップします。
  追加するとすぐに中身が調べられ、含まれるボリュームが一覧に出ます。
- **物理ディスク**:PC に接続されているディスクです。このセクションは**既定で折りたたまれています**
  (見出しをクリックすると展開されます)。「ディスクを読み取る」を押すまで何も読みません。押すと管理者権限の承認を求められます(後述)。

ボリュームごとにドライブ文字(または「自動」)を選び、「マウント」を押します。マウント中のボリュームは上部に表示され、
「フォルダーを開く」と「マウント解除」が使えます。複数のボリュームを持つ APFS コンテナでは、
Mac のユーザーファイルがある **Data** ボリュームが「おすすめ」になります。
暗号化された APFS ボリュームは一覧に出ますが、マウントできません。

ウィンドウはライトテーマです(Segoe UI と游ゴシック)。ウィンドウを閉じる、または最小化すると、**システムトレイ**に移り、
トレイのアイコンからバルーン通知でお知らせします。トレイのアイコンをクリックすると戻ります。
メニュー(「ウィンドウを表示」「すべてアンマウント」「終了」)も使えます。終了すると、すべてのマウントが解除されます。
2 回目の起動は、実行中のウィンドウを前面に出すだけです。表示言語は、日本語の Windows では日本語、それ以外では英語です
(`APFSREADER_LANG=en` または `ja` で切り替えられます)。コマンドライン:追加するイメージのパス、すぐにマウントする `--mount`、
トレイで起動する `--minimized`。

### 物理ディスクと管理者権限

生のディスクの読み取りには管理者権限が必要ですが、昇格したプログラムが作ったドライブ文字は、通常のエクスプローラーには表示されません。
そのため、アプリとマウントは通常のユーザー権限で動かし、小さなヘルパー `apfsreader-broker.exe` だけを昇格します(UAC の確認は 1 回です)。
このヘルパーは、

- **物理ディスク 1 台を読み取り専用**で開くだけです(ファイルのパスは受け付けず、保護されたファイルの読み取りには使えません)。
  書き込みの機能そのものがありません。
- あなたのアカウントだけが開ける名前付きパイプで読み取りを提供し、リモートからの接続を拒否し、起動時に渡されるランダムなトークンを要求します。
- アプリが切断すると直ちに終了します。90 秒以内に誰も接続しなければ、自分で終了します。

アプリをすでに管理者として起動した場合は、ヘルパーなしでディスクを直接読みます。
ディスクの一覧表示には権限が要らないため、一覧はすぐに出ます。

## コマンドライン

```
apfsreader disks                                          # 物理ディスクの一覧
apfsreader info    image.dmg
apfsreader ls      image.dmg /Documents
apfsreader extract image.dmg /Documents D:\rescued        # フォルダーごとコピー。-v でファイル名を表示
apfsreader-mount   image.dmg R:                           # Enter か Ctrl+C で解除
```

`image` には、生イメージ、UDIF の `.dmg`、GPT または Apple パーティションマップを持つディスク全体のイメージ、
`\\.\PhysicalDriveN`(管理者として実行。エクスプローラーに見えるドライブにしたい場合は、アプリを使ってください)を指定できます。
`--part N` でパーティションを、`--vol N` で APFS のボリュームを選びます(既定:Data ボリュームがあればそれ)。

`extract` はデータ救出向けです。読み取りエラーがあっても続行し、壊れたファイルは読めた部分を残し、最後にすべての問題を表示して、
問題があれば終了コード 3 で終わります。Windows で使えない名前(`:`、`?`、`CON` のような予約名)は、似た文字に置き換えます。
シンボリックリンクは `名前.symlink` というテキストファイルとして書き出されます。
`APFSREADER_TRACE=1` を付けると、`apfsreader-mount` がすべての要求をログに出します。

## 対応していること

- **ファイルシステム**:HFS+、HFSX、APFS(現在の状態。スナップショットは扱いません)。
- **コンテナ**:生イメージ、UDIF(zlib、bzip2、LZFSE、XZ 形式の LZMA、ADC)、GPT(512 バイトと 4Kn セクタ)、Apple パーティションマップ。
- **ファイル**:ハードリンク、シンボリックリンク、拡張属性、リソースフォーク、透過圧縮(decmpfs の型 1、3/4、7/8、11/12)。
- **HFS+ のジャーナル**:正しく取り外されなかったボリュームは、ジャーナルを再生した後の状態で読みます。再生はメモリ上で行い、何も書き込みません。
- **書き込みは一切しません。** マウントは読み取り専用で、どの部品にも書き込みの経路がありません。

## 対応していないこと

- 暗号化された APFS ボリューム(誤って読まずに、拒否します)と Fusion Drive のコンテナ。
- decmpfs の型 9/10、13/14(LZBITMAP)、5:該当するファイルはエラーになります。
- APFS のスナップショット、シール済みボリュームの詳細、System/Data のボリュームの組を統合した表示。
- 別のデバイスにある HFS+ のジャーナル。
- Windows のリンクとしてのシンボリックリンク:リンク先を書いた小さなファイルとして見えます。
- ディスクを挿した瞬間の自動認識:ウィンドウを開いている間は数秒おきに一覧を更新します。「更新」でも更新できます。

## どれくらい検証されているか

`cargo test`(129 件)、`scripts\test-mount.ps1`(テスト画像をマウントして、Windows のファイル API 経由で確認)、
`scripts\test-gui.ps1`(実際のウィンドウを操作)が、すべて通っています。スクリプトの実行には、先に `cargo build --release` が必要です。

- **実際の macOS が作った出力**:`testdata/macos-fixtures` には、`hdiutil`、`ditto`、`xattr` で作った画像があり、
  作成時に記録した SHA-256 のマニフェストが付いています(go-apfs-v2 のリポジトリのもので、作り方はそちらの `scripts/gen-fixtures.sh` にあります)。
  APFS と HFS+ について、生イメージ、GPT、APM、上記のすべての DMG コーデックで、全エントリを確認しています。
  `testdata/UNENCRYPTED.dmg` は 2017 年の Disk Utility が作った画像、`testdata/nps-hfsjtest1` は NPS コーパスのジャーナル付き HFS+ ボリュームで、
  そのログから、ジャーナルの構造と 512 バイトのブロック単位を確かめました。
- **実際の出力では一部しか確認できていないもの**:decmpfs の型のうち、実画像に含まれるのは、リソースフォークの LZVN(型 8)だけです。
  zlib と LZFSE は、合成データによる検証です。ジャーナルの再生は、本物のジャーナルを、異常終了した状態のように巻き戻し、
  書き換え対象のブロックを壊して確認するテストと、末尾で折り返す手作りのログ(両方のバイト順)で確認しています。
  **クラッシュで本当に汚れたボリュームの画像は、1 つもありません。**
- **物理ディスク:ディスクそのもの以外は確認済み**:実際のディスクの一覧、セクタ境界に合わせた読み取り層(境界に違反する要求を拒否する偽デバイスで確認)、
  4Kn のパーティションテーブル、実際の名前付きパイプ上のヘルパーのプロトコル(誤ったトークン、過大な読み取り、時間切れ)、
  そのパイプ経由でのボリューム全体の読み取りを、テストしています。
  **確認できていないのは、実物の物理ディスクの読み取り、UAC の承認画面、昇格したヘルパーです。** 実機と管理者セッションが必要なため、実機での初回が本当のテストになります。
- **ウィンドウ**:レイアウト、状態管理、各ボタンの動作(偽のバックエンドで)、最小化してトレイへ、非表示からの復帰、閉じるボタンでトレイへ、
  実際のウィンドウ経由でのマウントと解除を確認しています。
  **確認できていないのは、トレイのアイコンやメニューを手でクリックする操作、エクスプローラーのウィンドウそのもの、Windows の通知領域のオーバーフロー、ファイル選択ダイアログです。**
- **堅牢性**:すべてのテスト画像の破損コピー(ランダムなビット反転。長時間の実行で数万個)を最後まで走査し、結果はエラーか正しいデータで、パニックしないことを確認しています。
  `FUZZ_ROUNDS=20000 cargo test --test fs_robustness` で長時間の試験を実行できます。

go-apfs-v2 の画像(`scripts/gen-testdata.ps1`)は、解析の相互確認には使えますが、Apple のものではなく、第三者の書き込みの結果です。

## ビルド

Rust(MSVC ツールチェーン)が必要です。マウントのクレートは bindgen のために libclang を必要とし、プロジェクトは `tools/libclang` から探します
(`python -m pip install --target tools/libclang libclang`)。マウントには WinFsp が必要です。

```
cargo build --release
cargo test
```

`apfsreader-gui.exe` は、同じフォルダーに `apfsreader-broker.exe` があることを前提にしています。`testdata/` のテスト画像は、
他のプロジェクトのものなので、ソースの配布物には含まれません。画像が必要なテストは、画像がなければ自動でスキップされます。
合成画像は `scripts/gen-testdata.ps1` で再生成できます。画像の入手先は `testdata/README.md` にあります。
